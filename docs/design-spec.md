# Nexthrum 设计规范

## 1. 设计原则

- 消息优先、信息层级清楚、减少干扰；支持系统外观与可访问性。
- 跨平台保持产品语义一致，但使用平台原生控件、导航、窗口与菜单行为，不逐像素复制。
- 当前 Windows 界面以暗色和蓝色主色为基线；macOS 首版遵循 SwiftUI/macOS 原生外观，支持系统浅色/深色外观。共享品牌色通过语义 token 映射，不强制相同控件样式。

## 2. 信息架构

- Windows 连接状态 UI 展示 disconnected/connecting/connected 三态，connecting 使用动效但同时提供可访问文本，状态仅由后端状态事件驱动。
- 设置：Gotify 服务器/令牌、连接测试、启动与窗口行为、保留天数、DND 时段。
- 常驻入口：Windows 托盘；macOS 菜单栏入口，包含打开消息、设置和退出。
- Windows 托盘在有未读时显示右上角红点，并通过 tooltip 显示「Nexthrum — N 条未读」；计数来源于后端权威快照（每次 `unread-count-changed` 同步刷新）。

## 3. 消息列表与状态

- 按消息时间倒序；列表支持滚动和空状态。
- 时间显示统一规则（两平台一致）：**当天**只显示 `HH:mm`；**同年**显示 `MM-DD HH:mm`；**跨年**显示 `YYYY-MM-DD`。完整时间仅用于 tooltip / 辅助技术文本。
- Windows 与 macOS 均采用同一卡片式规格：`apps/windows` 的 `MessageHeader` + `MessageItem`，macOS 的 `MessageRow`/`MessageCard` + `headerBar`；两侧都提供顶部来源筛选、连接状态与重连入口。
- 消息列表采用卡片式呈现：每条消息独立圆角卡片（10pt 圆角、8pt 间距、悬停轻微抬升阴影），未读卡片使用强调色淡底 + 描边；卡片底部展示来源与优先级徽标。
- 列表顶部为头部栏：视图标题、未读胶囊、连接状态点、缓存条数与连接/设置动作；存储异常以横幅形式呈现。
- 已读/未读必须同时用多个冗余线索表达，不能只靠颜色：未读行使用强调色竖条 + 圆点 + 加粗标题，已读行标题转次要色、正文降低对比。两平台均按此实现（macOS `MessageRow`、Windows `MessageItem`），并保留右键「标记为已读 / 删除」与行级无障碍标签。
- 未读状态须同时有非颜色提示（图标/字重等），辅助技术可读。
- 点击打开/复制等交互需一致且可发现；删除使用明确的上下文操作和必要确认。
- 来源名称优先使用 Gotify `/application` 返回的真实应用名；无法获取时（受限服务器/离线）回退为 `App <id>`，两平台都需保持这一降级行为。
- 消息列表头部提供搜索框（带清除按钮）；进入搜索时隐藏来源筛选条，未命中时显示空状态并回显查询词。
- 首次运行且未配置服务器时显示引导页：三步说明（服务器地址、客户端令牌在 Gotify 网页端 Clients 获取、先测试再保存）+ 内联表单 + 「保存并连接 / 暂时跳过 / 高级设置」。
- 自动更新以**非阻塞横幅**呈现（有新版本 → 下载更新 → 立即重启），不遮挡列表；离线或清单缺失时静默不提示。
- 消息列表顶部在来源 ≥2 时展示胶囊式来源筛选条：`All` 与每个来源的标签（Gotify 仅提供 appid 时回退为 `App <id>`），并显示各自消息数与未读数；选中项用强调色填充，来源消失时自动回到 `All`。
- 新消息到达、标读、删除和清空后，列表及未读数即时保持一致。

## 4. 平台布局

### Windows
- 沿用当前桌面窗口布局（默认 800×600，最小 400×300，实际尺寸可按实现调整）。
- 当前无边框自定义标题栏属于 Windows 视觉实现，不作为跨平台硬约束。
- 关闭至托盘行为应明确提示并可配置。

### macOS
- 使用 SwiftUI `MenuBarExtra`（`.window` 样式）提供紧凑面板：未读计数、最近 3 条消息（点击打开并标读，右键可标读/删除），以及 Open Messages、Settings、Quit；关闭主窗口不终止后台连接，明确退出才结束应用。
- 连接异常时面板与主窗口都显示断开原因（TLS、鉴权、超时等），并提供 Reconnect 操作。
- `AppLifecycleDelegate` 设置最后一个窗口关闭后不退出；通知点击通过 AppModel 状态重新打开主窗口并定位消息。

## 5. 通知与权限

- 通知标题优先显示 Gotify 消息标题，正文显示消息内容摘要。
- DND 时不推送系统通知，但消息仍保存。
- macOS 首次需要通知时解释用途并请求系统授权；拒绝后仍可在应用内查看消息。
- 点击通知打开主界面并尽可能定位消息；系统不允许时提供清楚的降级行为。

## 6. 视觉与交互

- Windows 当前 CSS 变量是现有实现参考：背景 `#1a1a2e`、面板 `#16213e`、主色 `#3b82f6`、文字 `#e2e8f0`、次要文字 `#94a3b8`、危险色 `#ef4444`、成功色 `#22c55e`。重构时将其视作语义色，而非固定平台皮肤。
- macOS 优先使用系统颜色、字体、控件状态、焦点环和标准键盘操作；品牌色只用于关键强调。
- 破坏性操作需二次确认并说明是否影响服务器端；保存/连接错误以可操作的文字反馈呈现。
- 支持键盘导航、合理对比度、动态字体/辅助技术标签；不能仅用颜色表达连接和已读状态。

## 7. 文案与本地化

- 支持简体中文与英文；新增文案通过本地化资源管理，不在业务层硬编码 UI 字符串。
- macOS 使用 `Resources/Localizable.xcstrings`（String Catalog）；静态 SwiftUI 字面量自动作为 key，动态文案走 `L10n.t(key)`。新增 key 必须同时提供 en 与 zh-Hans，`LocalizationTests` 会校验键集合一致。
- 语言默认跟随系统；Windows 允许在设置中切换并持久化到本地存储（`nexthrum.locale`），macOS 首版跟随系统语言。
- **禁止用本地化字符串做逻辑判断**（如比较 `connectionLabel == "Connecting…"`）：状态必须用枚举/布尔表达，展示层再本地化。
- 时间、日期和数字使用当前区域设置格式化；网络/存储错误需给出简明用户提示，详细诊断仅进入脱敏日志。
