# Nexthrum 设计规范

## 1. 设计原则

- 消息优先、信息层级清楚、减少干扰；支持系统外观与可访问性。
- 跨平台保持产品语义一致，但使用平台原生控件、导航、窗口与菜单行为，不逐像素复制。
- 当前 Windows 界面以暗色和蓝色主色为基线，同时规划白天/浅色模式与跟随系统模式；macOS 首版遵循 SwiftUI/macOS 原生外观，支持系统浅色/深色外观。共享品牌色通过语义 token 映射，不强制相同控件样式。Windows 端详细重构计划见 `docs/windows-ui-redesign-plan.md`。

## 2. 信息架构

- Windows 连接状态 UI 展示 disconnected/connecting/connected 三态，connecting 使用动效但同时提供可访问文本，状态仅由后端状态事件驱动。
- 设置：Gotify 服务器/令牌、连接测试、启动与窗口行为、保留天数、DND 时段。
- 常驻入口：Windows 托盘；macOS 菜单栏入口，包含打开消息、设置和退出。
- Windows 托盘在有未读时显示右上角红点，并通过 tooltip 显示「Nexthrum — N 条未读」；计数来源于后端权威快照（每次 `unread-count-changed` 同步刷新）。

## 3. 消息列表与状态

- 按消息时间倒序；列表支持滚动和空状态。
- 时间显示统一规则（两平台一致）：**当天**只显示 `HH:mm`；**同年**显示 `MM-DD HH:mm`；**跨年**显示 `YYYY-MM-DD`。完整时间仅用于 tooltip / 辅助技术文本。
- Windows 与 macOS 均采用同一卡片式规格：`apps/windows` 的 `MessageHeader` + `MessageItem`，macOS 的 `MessageRow`/`MessageCard` + `headerBar`；两侧都提供顶部来源筛选、连接状态与重连入口。
- 消息列表采用卡片式呈现：每条消息独立圆角卡片（10pt 圆角、8pt 间距、悬停轻微抬升阴影），未读卡片使用强调色淡底 + 描边；卡片底部展示来源与优先级徽标。
- 列表顶部为头部栏：视图标题、未读胶囊、连接状态点、缓存条数与连接/设置动作；存储异常以横幅形式呈现。
- 已读/未读必须同时用多个冗余线索表达，不能只靠颜色：未读行使用强调色竖条 + 圆点 + 加粗标题，已读行标题转次要色、正文降低对比。两平台均按此实现（macOS `MessageRow`、Windows `MessageItem`），并保留右键「标记为已读 / 删除」与行级无障碍标签。
- 未读状态须同时有非颜色提示（图标/字重等），辅助技术可读。
- 点击打开/复制等交互需一致且可发现；删除使用明确的上下文操作和必要确认。
- 来源名称优先使用 Gotify `/application` 返回的真实应用名；无法获取时（受限服务器/离线）回退为 `App <id>`，两平台都需保持这一降级行为。
- 消息列表头部提供搜索框（带清除按钮）；进入搜索时隐藏来源筛选条，未命中时显示空状态并回显查询词。
- 首次运行且未配置服务器时显示引导页：三步说明（服务器地址、客户端令牌在 Gotify 网页端 Clients 获取、先测试再保存）+ 内联表单 + 「保存并连接 / 暂时跳过 / 高级设置」。
- 自动更新以**非阻塞横幅**呈现（有新版本 → 下载更新 → 立即重启），不遮挡列表；离线或清单缺失时静默不提示。
- 消息列表顶部在来源 ≥2 时展示胶囊式来源筛选条：`All` 与每个来源的标签（Gotify 仅提供 appid 时回退为 `App <id>`），并显示各自消息数与未读数；选中项用强调色填充，来源消失时自动回到 `All`。
- 新消息到达、标读、删除和清空后，列表及未读数即时保持一致。

## 4. 平台布局

### Windows 白天/浅色模式

- 白天模式不是简单将深色背景替换为纯白，而是使用冷灰蓝窗口背景（建议 `#f3f6fb`）、白色面板、清晰的浅灰蓝边框和深色文本建立层级。
- 标题栏、页面头部、表单分组和消息卡片使用白色或近白色；主要层级通过边框、间距和轻微阴影区分，避免所有区域融为一体。
- 主文本建议使用深蓝灰色（如 `#172033`），次要文本使用中等蓝灰色（如 `#53627a`），不得使用低对比度浅灰文字。
- 主色使用较深的 Windows 蓝（建议 `#2563c7`），用于主按钮、链接、焦点、未读竖条和选中状态；悬停状态使用更深的蓝色。
- 消息卡片使用明确边框；未读消息使用浅蓝底、蓝色竖条、圆点和加粗标题，不能只依赖颜色表达未读。
- 输入框获得焦点时显示蓝色边框和外环；按钮必须区分悬停、按下、禁用和键盘焦点状态。
- 成功、警告和错误颜色必须在白色背景上保持足够对比度，并配合图标、文字或状态标签表达。
- 弹窗和上下文菜单使用白色背景、清晰边框和柔和阴影；页面背景使用冷灰蓝，避免大面积纯白造成视觉疲劳。
- 白天、深色和跟随系统模式切换时不得改变布局尺寸或控件位置。主题实现使用语义色 Token，不在组件中硬编码主题颜色。

### Windows
- 采用**竖版窗口**（默认 460×760，最小 380×420）：消息流是按时间排列的单列，宽屏横向窗口在 Windows 上浪费横向空间、拉长阅读视线；竖版也更接近 macOS 菜单栏面板的形态。
- 视觉方向为**类 macOS 的极简扁平风**：不使用卡片描边+阴影的堆叠，改用「白色内容面 + 细分割线 + 大留白」；强调色只用于主操作、选中态、未读提示与链接。
- 采用无边框自定义标题栏（`decorations: false`），高度 34px，从左到右为：应用图标 + 产品名 `Nexthrum`（次要色小字）、可拖动空白区、最小化 / 最大化-还原 / 关闭三个窗口按钮；关闭按钮悬停使用危险色。标题栏与页面头部使用同一 surface，仅以 1px 分割线区分。
- 标题栏支持双击最大化/还原；拖动区与按钮区必须分离，点击按钮不得触发窗口拖动；最大化状态需与窗口实际状态同步（监听窗口尺寸事件）。
- 页面内容统一使用居中容器（列表与头部 `max-w-2xl`，设置与引导 `max-w-md`～`xl`）+ 左右内边距：标题栏、页面头部、筛选条、列表和设置正文在同一垂直基准线上。

### Windows 消息头部按钮语义
- 头部右侧固定三个互不混淆的动作：**重新连接**（图标）、**主题切换**（图标：深色显示太阳、白天显示月亮，点击在深色/白天之间切换）、**设置**（纯文字，不带图标）。
- 设置入口**不得**使用齿轮/太阳类图标：齿轮容易被理解为主题或系统设置，且与主题按钮视觉冲突。
- 未读数以标题右侧的次要色数字呈现，不使用高饱和大胶囊。
- 关闭至托盘行为应明确提示并可配置。

### macOS
- 使用 SwiftUI `MenuBarExtra`（`.window` 样式）提供紧凑面板：未读计数、最近 3 条消息（点击打开并标读，右键可标读/删除），以及 Open Messages、Settings、Quit；关闭主窗口不终止后台连接，明确退出才结束应用。
- 连接异常时面板与主窗口都显示断开原因（TLS、鉴权、超时等），并提供 Reconnect 操作。
- `AppLifecycleDelegate` 设置最后一个窗口关闭后不退出；通知点击通过 AppModel 状态重新打开主窗口并定位消息。
- 设置页可关闭「在程序坞中显示图标」：关闭后应用切为 `.accessory` 激活策略（无程序坞图标、无 ⌘-Tab 条目），只保留菜单栏入口；偏好持久化，下次启动直接进入纯菜单栏模式且不弹出主窗口。

## 5. 通知与权限

- 通知标题优先显示 Gotify 消息标题，正文显示消息内容摘要。
- DND 时不推送系统通知，但消息仍保存。
- macOS 首次需要通知时解释用途并请求系统授权；拒绝后仍可在应用内查看消息。
- 点击通知打开主界面并尽可能定位消息；系统不允许时提供清楚的降级行为。

## 6. 视觉与交互

- Windows 语义色（类 macOS）：**白天** 背景 `#f5f5f7`、内容面 `#ffffff`、悬停 `#ededf0`、分割线 `#e2e2e6`、主色 `#0071e3`、主文字 `#1d1d1f`、次要 `#63636a`、弱化 `#8e8e93`；**深色** 背景 `#1c1c1e`、内容面 `#232326`、悬停 `#323235`、分割线 `#3a3a3d`、主色 `#0a84ff`、主文字 `#f5f5f7`、次要 `#a1a1a6`。
- 扁平规则：内容面之间不用描边+阴影区分，优先用 1px 分割线与大留白；卡片阴影 `--shadow-card` 恒为空值，仅弹窗/右键菜单保留 `--shadow-popover`。圆角统一 8px（控件）/ 12px（分组块、弹窗）。
- Windows 主题以语义 Token 实现（`apps/windows/src/styles/index.css`）：深色为 `:root` 默认，白天为 `:root[data-theme="light"]`；`data-theme` 由 `apps/windows/src/theme/useTheme.ts` 写入，支持「跟随系统 / 白天 / 深色」并在设置页切换，偏好保存在本机 `localStorage`（`nexthrum.theme`）。组件禁止硬编码主题色，只使用 `--color-*` Token。
- Windows 基础控件统一由 `apps/windows/src/components/ui/` 提供（`Button`、`IconButton`、`Input`、`Field`、`Switch`、`Section`、`SegmentedControl`、`PageHeader`、`EmptyState`）；新增页面必须复用这些控件，不得再复制粘贴按钮/输入框样式。
- macOS 优先使用系统颜色、字体、控件状态、焦点环和标准键盘操作；品牌色只用于关键强调。
- 破坏性操作需二次确认并说明是否影响服务器端；保存/连接错误以可操作的文字反馈呈现。
- 支持键盘导航、合理对比度、动态字体/辅助技术标签；不能仅用颜色表达连接和已读状态。

## 7. 文案与本地化

- 支持简体中文与英文；新增文案通过本地化资源管理，不在业务层硬编码 UI 字符串。
- macOS 使用 `Resources/Localizable.xcstrings`（String Catalog）；静态 SwiftUI 字面量自动作为 key，动态文案走 `L10n.t(key)`。新增 key 必须同时提供 en 与 zh-Hans，`LocalizationTests` 会校验键集合一致。
- 语言默认跟随系统；Windows 允许在设置中切换并持久化到本地存储（`nexthrum.locale`）；macOS 设置页同样可用「跟随系统 / English / 简体中文」切换，选择写入 `AppleLanguages`，重启应用后菜单、菜单栏与通知文案一并生效（切换后给出「立即重新启动」入口）。
- **禁止用本地化字符串做逻辑判断**（如比较 `connectionLabel == "Connecting…"`）：状态必须用枚举/布尔表达，展示层再本地化。
- 时间、日期和数字使用当前区域设置格式化；网络/存储错误需给出简明用户提示，详细诊断仅进入脱敏日志。
