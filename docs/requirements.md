# Nexthrum 产品需求

## 1. 产品定位

Nexthrum 是 Gotify 桌面消息客户端，连接用户配置的 Gotify 服务器，实时接收消息并在本机展示和通知。产品面向 Windows 与 macOS，两个平台使用各自原生桌面体验，共享一致的消息和连接行为。

## 2. 平台与实现状态

| 平台 | 当前实现 | 目标实现 |
|---|---|---|
| Windows | Tauri 2 + React 18/TypeScript；业务在共享 Rust Core，Tauri 仅作平台适配 | 保持现状 |
| macOS | SwiftUI + 共享 Rust Core（UniFFI）；UserNotifications 投递与通知点击导航；Keychain 凭据 | 保持现状；Apple Silicon（arm64）；最低 macOS 14.0 |

本文件描述目标产品行为。2.0.0 已发布 Windows 与 macOS（arm64）两个平台；未落地的内容会明确标注为待实现，不应视作文档即已具备。

## 3. 核心需求

### 3.0 消息搜索

- 消息列表提供搜索框，按**标题与正文**做不区分大小写的子串匹配（`%`、`_` 按普通字符处理）。
- 搜索在本地 SQLite 中执行，最多返回 500 条；未读计数始终显示全局值，不随搜索变化。
- 输入停顿 250ms 后才发起查询，过期请求结果必须丢弃；清空搜索立即恢复完整列表与来源筛选。
- 无匹配时显示明确的空状态并带出查询词。

### 3.0.1 首次运行引导

- 未配置服务器时展示引导页，说明需要填写服务器地址与客户端令牌，并指出令牌在 Gotify 网页端 *Clients* 获取。
- 引导页提供连接测试、保存并连接、暂时跳过与进入完整设置四类操作；保存成功后自动进入消息列表。
- 不得因访问钥匙串而阻塞首次启动：未配置时不读取系统凭据。

### 3.1 Gotify 连接
- 桌面端在启动后自动检查更新（Windows）；发现新版本时以非阻塞横幅提示，支持「下载更新」与「立即重启」，也可暂不更新。
- 更新包必须带有效签名，校验失败不得安装；离线或清单缺失时静默跳过，不打断使用。

- 配置一个 Gotify Server URL 与 Client Token。
- 提供连接测试，清晰显示成功、鉴权失败、网络失败等结果。
- 通过 Gotify WebSocket 实时接收消息；连接中断后自动恢复，并显示连接状态。
- 修改或清空连接配置后，旧连接必须按新配置重连或断开。
- Token 属于敏感信息，不得写入日志；优先使用平台凭据存储。

### 3.2 消息管理
- 消息去重：按 Gotify message ID 幂等更新；重复投递保留本地已读状态，不重复触发新消息通知。
- 支持按 Gotify App 来源筛选。
- 支持查看消息、复制内容、标记已读、删除单条和清空本地消息。
- 清空本地记录与删除服务器端记录是不同操作；选择同步删除时，服务器失败必须明确报错并保留本地记录，不得静默报告成功。
- 展示未读数量；消息变更后计数必须一致。

### 3.3 通知与免打扰
- 新消息默认发送系统原生通知；用户可在系统权限中控制授权。macOS 依据 Core `should_notify` 策略发送，通知授权、拒绝状态和点击导航需保持可见、可恢复。
- Windows 通知点击当前由系统默认激活处理（聚焦应用窗口），**不做消息级定位**：`tauri-plugin-notification` 未暴露 Windows toast 的 Activated 事件。若需要与 macOS 一致的「点击定位消息」，需接入 COM `ToastNotification` 激活回调，已列为后续任务；在此之前托盘未读红点与窗口内未读标记承担定位辅助。
- 免打扰时段内不发送通知，但仍接收和保存消息；支持跨午夜时间范围。
- 点击通知打开消息界面，并尽可能定位至对应消息。

### 3.4 常驻与生命周期
- Windows 提供系统托盘入口：消息列表、设置、退出。
- macOS 提供原生 `MenuBarExtra` 紧凑面板：显示未读计数与最近 3 条消息，可直接打开、标读或删除；同时提供打开消息、设置、退出。关闭最后一个主窗口后连接继续运行，明确退出才结束应用。
- macOS 可隐藏程序坞图标（`.accessory` 策略，同时从 ⌘-Tab 移除），隐藏后仅通过菜单栏面板访问；偏好持久化，启动时直接停在菜单栏而不弹主窗口。
- 支持配置开机启动（受操作系统授权和 API 限制）。
- 关闭窗口不应意外终止后台连接；用户可通过明确的退出操作结束应用。

### 3.5 设置
- Server URL、Client Token；macOS 设置页同时支持消息保留天数和 DND 开始/结束时间。
- macOS 设置增加 Launch at login 开关和系统授权/注册状态；服务使用 `SMAppService.mainApp`，注册失败不回滚已保存的连接设置。
- macOS 设置增加外观分组：程序坞图标显示开关（`UserDefaults` 持久化，不进 `BridgeSettings`）与界面语言（跟随系统 / English / 简体中文，切换后需重启生效）。
- macOS 设置增加「更新」分组：自动检查更新开关（写回 Sparkle 的 `automaticallyChecksForUpdates`）、「检查更新…」按钮（检查中禁用并显示进行态）与上次检查时间。
- 窗口/常驻行为（平台适配，不强求选项名称完全相同）。
- 消息保留天数，默认 7 天，定期清理过期消息。
- DND 开始/结束时间，默认 22:00–08:00。
- 设置保存失败必须保留旧配置并向用户显示错误。

## 4. 非功能需求
- 本地消息使用 SQLite；schema 通过迁移机制演进。
- 平台数据存储在操作系统推荐的应用数据目录；迁移不应导致已有用户数据丢失。
- Rust 核心逻辑可独立测试，不依赖 Tauri 或 SwiftUI。
- Windows 与 macOS 行为有共享契约测试；系统集成分别进行平台测试。
- 明确最低支持 Windows 版本；macOS 当前工程限定 Apple Silicon arm64、最低版本 14.0；发行格式和签名策略发布前确定。
- 凭据安全、错误可诊断、网络失败不静默丢失本地数据。

## 5. 暂不纳入范围

多服务器、消息搜索、富文本渲染、复杂优先级规则。需另行评估并更新需求。

## 6. 验收要点

- 两个平台均能配置、验证并连接 Gotify，断线可恢复。
- 新消息可靠落库，列表、已读状态和未读计数一致。
- DND、保留期、删除与清空行为符合上述定义。
- macOS UI 使用 SwiftUI，通知、菜单栏入口及启动项采用原生系统能力。
- Windows 既有用户数据和配置在重构后兼容；失败结果明确反馈。
